# Техническое задание: «Кинотека»

Документ для передачи исполнителю. Описывает продукт целиком: что должно
получиться, как это проверяется и по каким критериям работа принимается.

- **Версия:** 1.0
- **Тип:** веб-приложение, self-hosted
- **Приоритет платформ:** телевизор → планшет → телефон → десктоп

---

## 1. Что это и зачем

Личный кинотеатр на одного владельца и небольшой круг людей, которым он даёт
доступ. Три вещи в одном интерфейсе:

1. **Каталог всего** — практически любой фильм, сериал и шоу, с русскими
   названиями, описаниями, постерами, трейлерами, актёрами.
2. **Своя библиотека** — файлы владельца (диск, NAS, внешний накопитель)
   индексируются, получают обложки и играют прямо в сайте: русская дорожка,
   4K, HDR, субтитры, скачивание, ноль рекламы.
3. **Легальный переход** — для того, чего нет в библиотеке, показывается
   сервис с правами в стране пользователя, с переходом одним нажатием.

Главный сценарий: человек садится на диван, берёт пульт, открывает сайт на
телевизоре и через три нажатия смотрит кино с русской дорожкой в максимальном
качестве.

### 1.1. Границы работы

**Входит:** каталог, индексация библиотеки, плеер, скачивание, профили,
история просмотра, списки, поиск, интерфейс под ТВ/планшет/телефон, PWA,
развёртывание.

**Не входит:** транскодирование на лету, мобильные нативные приложения,
рекомендательные алгоритмы, платежи, социальные функции.

**Отдельно оговаривается:** приложение играет только то, на что у владельца
есть право — собственные файлы, материалы в общественном достоянии, сервисы, с
которыми у владельца есть договор или оплаченный API-доступ. Интеграции с
сервисами, раздающими чужой контент без прав, в объём работ не входят и
приёмку не проходят.

---

## 2. Пользователи и сценарии

| Роль | Что делает |
|---|---|
| Владелец | Разворачивает, настраивает папки с файлами, выдаёт код доступа |
| Зритель | Входит по коду, заводит профиль, смотрит, качает, ведёт свой список |

### Ключевые сценарии

**С-1. Досмотреть начатое.** Открыть сайт → первый ряд «Продолжить просмотр» →
нажать → фильм играет с той секунды, где остановились. **Не более трёх нажатий
от загрузки экрана.**

**С-2. Найти и посмотреть своё.** Поиск → ввести название → карточка с меткой
«в библиотеке» → страница фильма → «Смотреть».

**С-3. Найти то, чего нет.** Поиск → карточка без метки → страница фильма →
блок «Смотреть легально» с сервисами → переход.

**С-4. Сериал.** Страница сериала → вкладка сезона → список серий, где есть на
диске видно сразу → нажать серию → играет.

**С-5. Скачать в дорогу.** Страница фильма → «Скачать» → файл сохраняется на
устройство.

**С-6. Дать доступ другу.** Владелец сообщает код → друг вводит код и имя →
получает свой профиль со своей историей.

## 3. Функциональные требования

### 3.1. Вход

- Ф-1.1. Сайт закрыт общим кодом доступа. Код задаётся в конфигурации.
- Ф-1.2. Зритель вводит код и имя профиля; при совпадении имени с существующим
  подключается к нему.
- Ф-1.3. Сессия живёт не менее 180 дней. Телевизор не должен спрашивать код
  чаще раза в полгода.
- Ф-1.4. История, прогресс и списки — раздельные на профиль.
- Ф-1.5. Пустой код в конфигурации открывает сайт без входа (домашняя сеть).
- Ф-1.6. Подбор кода замедляется задержкой ответа не менее 500 мс.

### 3.2. Главный экран

- Ф-2.1. Крупный баннер с ротацией по нескольким тайтлам. Ротация
  останавливается, как только фокус попадает внутрь баннера.
- Ф-2.2. Ряды в фиксированном порядке:
  1. Продолжить просмотр (только если есть незавершённое)
  2. В моей библиотеке (только если библиотека не пуста)
  3. Сейчас смотрят
  4. Популярные фильмы
  5. Российское кино
  6. Популярные сериалы
  7. Сейчас в кино
  8. Лучшее за всё время
  9. Российские сериалы
  10. Лучшие сериалы
- Ф-2.3. Ряд, который не загрузился, пропускается. Экран с половиной рядов
  работает; пустой экран с ошибкой — нет.
- Ф-2.4. Карточка показывает постер, название, год; при фокусе — рейтинг.
- Ф-2.5. Карточка из библиотеки помечена; показывается лучшее качество (4K,
  1080p, HDR).
- Ф-2.6. Незавершённое показывается полосой прогресса поверх обложки.

### 3.3. Каталог, поиск, фильтры

- Ф-3.1. Поиск по всему каталогу, минимум 2 символа, запрос отправляется с
  задержкой 400 мс после последнего ввода.
- Ф-3.2. Тайтлы из своей библиотеки поднимаются в начало результатов.
- Ф-3.3. Разделы «Фильмы» и «Сериалы» с фильтром по жанру и сортировкой:
  популярность, рейтинг, сначала новые.
- Ф-3.4. Постраничная подгрузка кнопкой «Показать ещё».
- Ф-3.5. Раздел «Моя библиотека» — вся полка владельца по алфавиту, со
  счётчиком названий и файлов.
- Ф-3.6. Раздел «Буду смотреть» — личный список, добавление и удаление со
  страницы тайтла.

### 3.4. Страница тайтла

- Ф-4.1. Фон-кадр, постер, название, оригинальное название, слоган, описание.
- Ф-4.2. Метаданные: год, рейтинг, длительность, жанры, возрастной рейтинг,
  страна, режиссёр, сценарист.
- Ф-4.3. Актёрский состав с фотографиями, горизонтальным рядом.
- Ф-4.4. Действия: «Смотреть»/«Продолжить», «Трейлер», «В список»,
  «Скачать».
- Ф-4.5. Если файлов несколько — список с выбором: качество, HDR, размер,
  дорожки, число субтитров; у каждого своя кнопка скачивания.
- Ф-4.6. Если файла нет — блок «Смотреть легально» со списком сервисов,
  сгруппированных по типу (подписка, аренда, покупка, бесплатно), с переходом.
- Ф-4.7. Ряд «Похожее».
- Ф-4.8. Для сериала — вкладки сезонов и список серий: номер, название, кадр,
  описание, длительность, рейтинг, отметка наличия на диске, прогресс.
  Отсутствующие серии показываются приглушённо, но не скрываются.

### 3.5. Плеер

- Ф-5.1. Воспроизведение файла напрямую, без перекодирования.
- Ф-5.2. Докрутка с места остановки: если было пройдено больше 30 секунд и до
  конца оставалось больше минуты.
- Ф-5.3. Прогресс сохраняется каждые 15 секунд и при уходе со страницы, включая
  событие `pagehide` — телевизор выключают кнопкой, а не через меню.
- Ф-5.4. Управление: воспроизведение/пауза, перемотка ±10 секунд, полоса
  перемотки с показом буфера, время текущее и общее.
- Ф-5.5. Перемотка склеивается: серия нажатий даёт один переход, а не запрос на
  каждое нажатие.
- Ф-5.6. Выбор аудиодорожки. Если браузер не даёт переключать дорожки внутри
  контейнера — плеер сообщает об этом текстом, а не показывает неработающую
  кнопку.
- Ф-5.7. Выбор субтитров, включая выключение. Внешние файлы субтитров рядом с
  видео подключаются автоматически.
- Ф-5.8. Управление скрывается через 4 секунды бездействия, возвращается на
  любое нажатие.
- Ф-5.9. Ошибка воспроизведения показывает причину человеческим языком
  («устройство не поддерживает кодек») и предлагает повтор и возврат.
- Ф-5.10. Кнопка «Назад» на пульте сохраняет прогресс и возвращает на страницу
  тайтла.

### 3.6. Библиотека владельца

- Ф-6.1. Рекурсивный обход указанных папок, глубина не менее 8 уровней.
- Ф-6.2. Разбор имени файла: название, год, сезон, серия, разрешение, источник
  (Remux/BluRay/WEB-DL/HDTV/DVD), HDR, аудиокодеки, языки дорожек. Форматы,
  которые обязаны разбираться:
  ```
  Brother.1997.2160p.BDRemux.HDR.RUS.DTS-HD.mkv
  Интерстеллар (2014) 1080p BluRay RUS ENG.mp4
  Сериал/Season 1/Show.S01E05.1080p.WEB-DL.RUS.mkv
  Сериал/Сезон 2/Серия 3.mkv
  ```
- Ф-6.3. При наличии ffprobe читаются реальные потоки контейнера: дорожки, их
  языки, каналы, кодеки, встроенные субтитры, длительность, битрейт.
  Без ffprobe работа продолжается на разборе имён.
- Ф-6.4. Сопоставление с каталогом по названию и году; результат кэшируется,
  повторное сканирование не делает лишних запросов.
- Ф-6.5. Файл, который не удалось сопоставить, **всё равно доступен для
  просмотра** — с именем файла вместо постера. Скрывать медиа пользователя
  недопустимо.
- Ф-6.6. Повторное сканирование обрабатывает только новые и изменённые файлы
  (по размеру и времени изменения). Полное пересканирование — отдельной
  командой.
- Ф-6.7. Сканирование по расписанию, интервал настраивается.
- Ф-6.8. Сканирование не блокирует запуск: сайт открывается сразу.
- Ф-6.9. Внешние субтитры (`фильм.ru.srt`) подхватываются и отдаются в WebVTT.
- Ф-6.10. При нескольких копиях одного фильма они сортируются по качеству:
  разрешение, источник, HDR, битрейт.

### 3.7. Скачивание

- Ф-7.1. Любой файл библиотеки скачивается одной кнопкой.
- Ф-7.2. Заголовок `Content-Disposition` содержит имя файла и в ASCII-форме, и
  в `filename*=UTF-8''` — иначе кириллица ломается в части браузеров.
- Ф-7.3. Скачивание поддерживает докачку (байтовые диапазоны).

### 3.8. Настройки

- Ф-8.1. Язык интерфейса: русский, английский.
- Ф-8.2. Режим интерфейса: автоматически / телевизор / планшет / телефон /
  компьютер. Ручной выбор переопределяет автоопределение и запоминается.
- Ф-8.3. Переключатель «меньше анимаций».
- Ф-8.4. Выход из профиля.

## 4. Нефункциональные требования

### 4.1. Телевизор — критично

Это основная платформа, а не «ещё и на телике откроется».

- Н-1.1. **Управление только пультом.** Мышь и тач не подразумеваются.
- Н-1.2. **Геометрическая навигация.** Переход идёт к ближайшему элементу в
  направлении нажатия, с сильным предпочтением элементов на одной линии.
  «Вправо» вдоль ряда **не должно** уводить на соседний ряд.
- Н-1.3. **Память фокуса по рядам.** Переход вверх-вниз возвращает на ту
  карточку, где пользователь был в этом ряду, а не на ближайшую геометрически.
- Н-1.4. **Коды кнопок** обрабатываются и как `key`, и как `keyCode`, минимум:
  Tizen (Назад `10009`), webOS (Назад `461`, перемотка `227`/`228`),
  Fire TV, Android TV, обычная клавиатура. Медиа-кнопки пульта работают.
- Н-1.5. **Кнопка Назад** идёт по истории приложения, а не выходит из браузера.
- Н-1.6. Фокус всегда виден и никогда не теряется. Если фокус потерян —
  восстанавливается автоматически.
- Н-1.7. Безопасные поля по краям: контент не уезжает в overscan.
- Н-1.8. Размеры шрифтов и элементов — под просмотр с трёх метров.
- Н-1.9. Текст не чисто-белый на чисто-чёрном: на OLED и плазме это мажет.

### 4.2. Производительность

- Н-2.1. **Целевое железо:** телевизор 2019–2020 года. Проверка обязательна на
  реальном устройстве, эмулятор не считается.
- Н-2.2. Прокрутка рядов — плавная, без рывков. Анимируются только `transform`
  и `opacity`.
- Н-2.3. Ряды рендерятся окнами: карточки монтируются по мере приближения.
  **Размонтировать пройденные карточки нельзя** — сломается навигация назад.
- Н-2.4. Обложки грузятся лениво, с запасом не менее 600×1200 px, в размере под
  устройство. Полноразмерные постеры в сетке недопустимы.
- Н-2.5. Обложки отдаются со своего домена с длительным кэшем — одно соединение
  на всю сетку вместо соединения на постер.
- Н-2.6. Размытие (`blur`, `backdrop-filter`) и крупные тени отключаются на
  слабом классе устройств. Это главный источник просадок.
- Н-2.7. Размер бандла: **не более 150 КБ gzip** суммарно.
- Н-2.8. Открытие главного экрана на целевом телевизоре — **не более 4 секунд**
  до первого ряда.
- Н-2.9. Реакция на нажатие пульта — **не более 150 мс**.

### 4.3. Совместимость

- Н-3.1. Клиент собирается под **Chromium 61** и новее. Обоснование: webOS 4 —
  Chromium 53, webOS 5 — 68, Tizen 2020 — 76. Синтаксис новее целевого уровня
  даёт белый экран на телевизоре.
- Н-3.2. Проверенные платформы: Samsung Tizen, LG webOS, Android TV, Fire TV,
  Safari на iPad и iPhone, Chrome, Safari, Firefox на десктопе.
- Н-3.3. Функции, которых может не быть, проверяются перед использованием
  (`IntersectionObserver`, `aspect-ratio`, `audioTracks`) и имеют запасной путь.

### 4.4. Планшет и телефон

- Н-4.1. Те же компоненты, другая плотность; отдельной кодовой базы нет.
- Н-4.2. На телефоне навигация переносится в нижнюю панель.
- Н-4.3. Учитываются безопасные зоны (вырезы, домашний индикатор).
- Н-4.4. PWA: устанавливается на домашний экран, открывается на весь экран.
- Н-4.5. Офлайн работают оболочка приложения и просмотренные обложки.
  Видео через service worker **не проксируется** — это ломает перемотку в
  Safari.

### 4.5. Стриминг

- Н-5.1. Байтовые диапазоны по спецификации: `Accept-Ranges`, корректный
  `Content-Range`, код `206`.
- Н-5.2. Суффиксные диапазоны (`bytes=-500`) поддерживаются.
- Н-5.3. Диапазон за пределами файла даёт `416` с `Content-Range: bytes */размер`.
- Н-5.4. Оборванное соединение не оставляет висящих файловых дескрипторов и не
  пишется в лог как ошибка — при перемотке это норма.
- Н-5.5. Таймауты соединения рассчитаны на фильм целиком, а не на обычный
  запрос.

### 4.6. Безопасность

- Н-6.1. Ключ внешнего каталога **никогда не попадает в клиент**.
- Н-6.2. Сессионные куки подписаны, `HttpOnly`, `SameSite=Lax`, `Secure` за
  HTTPS.
- Н-6.3. Сравнение кода доступа — постоянное по времени.
- Н-6.4. Отдаются только файлы, попавшие в индекс. Произвольный путь с
  клиента принять невозможно.
- Н-6.5. Папки с медиа монтируются только на чтение.
- Н-6.6. Секреты только в переменных окружения, в репозитории — пример
  конфигурации без значений.

### 4.7. Отказоустойчивость

- Н-7.1. Отсутствие ключа каталога не роняет приложение: сайт поднимается и
  объясняет, чего не хватает.
- Н-7.2. Отсутствие папок с медиа не роняет приложение.
- Н-7.3. Внешний каталог отвечает ошибкой — показывается то, что закэшировано.
- Н-7.4. Состояние (профили, прогресс, списки) пишется атомарно и переживает
  выключение питания.

## 5. Архитектура

### 5.1. Стек

Сервер — Node.js (LTS). Клиент — React с TypeScript, сборка Vite. Хранилище —
JSON с атомарной записью; отдельная СУБД для десятка зрителей не нужна и
добавляет точку отказа. Отклонение от стека допускается только по согласованию
и с обоснованием.

### 5.2. Разделение слоёв

Ключевое архитектурное требование: **каталог и источник видео разделены.**
Каталог знает про все фильмы на свете; источник знает, откуда взять байты
конкретного файла. Источники подключаются как плагины и регистрируются в общем
реестре.

Провайдер источника обязан реализовать:

```js
{
  id: 'local',                 // уникальный, url-safe
  name: 'Моя библиотека',

  async getSources(titleId, { season, episode }) { /* -> Source[] */ },
  async openStream(sourceId, { range })          { /* -> поток + границы */ },

  async listTitles() {},       // необязательно: свой каталог
  async refresh()   {},        // необязательно: переиндексация
}
```

`openStream` возвращает объект с полями `stream`, `start`, `end`, `size`,
`totalSize`, `partial`, `mimeType`, `filename`; при выходе за границы файла —
`unsatisfiable: true`.

В объём работ входит один провайдер — локальная библиотека. Интерфейс должен
быть задокументирован так, чтобы новый провайдер добавлялся без правок в
каталоге, плеере и интерфейсе.

### 5.3. Структура API

```
GET  /api/health                     состояние, наличие ключа, статистика
GET  /api/auth/state                 нужен ли вход, текущий профиль
POST /api/auth/login                 код + имя -> сессия
POST /api/auth/logout

GET  /api/catalog/home               ряды главного экрана + баннер
GET  /api/catalog/genres
GET  /api/catalog/browse             фильтры, сортировка, страница
GET  /api/catalog/search             поиск, своё поднято вверх
GET  /api/catalog/library            вся полка владельца

GET  /api/titles/:id                 карточка + источники + прогресс
GET  /api/titles/:id/season/:n       серии + наличие на диске

GET  /api/playback/sources/:id       что можно посмотреть
GET  /api/playback/stream/:p/:s      поток с диапазонами
GET  /api/playback/download/:p/:s    скачивание
GET  /api/playback/subtitle/:p/:s/:x субтитры в WebVTT

POST /api/user/progress              сохранение позиции
GET  /api/user/watchlist
POST /api/user/watchlist             добавить/убрать

GET  /api/img/:size/:path            прокси обложек с кэшем
```

Идентификатор тайтла — строка вида `movie:603` / `tv:1396`, единая для каталога
и источников.

## 6. Приёмка

Работа принимается, если **все** пункты проходят. Проверка делается заказчиком
на реальном телевизоре и реальном планшете, не на скриншотах.

### 6.1. Функциональные проверки

| № | Проверка | Ожидаемо |
|---|---|---|
| П-1 | Запуск без ключа каталога и без папок с медиа | Сайт открывается, объясняет, чего не хватает |
| П-2 | Запуск с ключом и папкой из 20+ файлов | Все файлы в библиотеке, названия и годы распознаны |
| П-3 | Файл `Название.2019.2160p.BDRemux.HDR.RUS.mkv` | 4K, HDR, русская дорожка, год 2019 |
| П-4 | Файл сериала `S01E05` во вложенной папке | Сериал, сезон 1, серия 5 |
| П-5 | Файл с непонятным именем | Доступен для просмотра, показывается имя файла |
| П-6 | Повторное сканирование без изменений | Ни одного нового запроса к каталогу |
| П-7 | Просмотр, выход на середине, возврат | Ряд «Продолжить», докрутка на ту же секунду |
| П-8 | Выключение телевизора во время просмотра | Позиция сохранена (проверка после включения) |
| П-9 | Скачивание файла с кириллицей в имени | Имя не побилось |
| П-10 | Два профиля | Истории и списки не пересекаются |
| П-11 | Тайтл, которого нет на диске | Блок с легальными сервисами, переход работает |

### 6.2. Технические проверки

| № | Проверка | Ожидаемо |
|---|---|---|
| П-12 | `curl -H 'Range: bytes=100-199'` | `206`, `Content-Range: bytes 100-199/размер` |
| П-13 | `curl -H 'Range: bytes=-50'` | `206`, последние 50 байт |
| П-14 | `curl -H 'Range: bytes=99999999-'` | `416`, `Content-Range: bytes */размер` |
| П-15 | Размер собранного бандла | ≤ 150 КБ gzip |
| П-16 | Поиск ключа каталога в бандле | Не найден |
| П-17 | Прямой запрос файла вне индекса | Отказ |
| П-18 | Прерывание потока на середине | Нет ошибок в логе, нет утечки дескрипторов |

### 6.3. Проверки на телевизоре

| № | Проверка | Ожидаемо |
|---|---|---|
| П-19 | Проход крестовиной по всем рядам главного экрана | Фокус нигде не теряется, не прыгает между рядами по горизонтали |
| П-20 | Вход в ряд, уход вверх, возврат вниз | Фокус вернулся на ту же карточку |
| П-21 | Кнопка Назад на пульте | Возврат по истории, не выход из браузера |
| П-22 | Открытие главного экрана | Первый ряд виден за ≤ 4 секунды |
| П-23 | Прокрутка длинного ряда | Плавно, без рывков |
| П-24 | Перемотка вперёд и назад в плеере | Картинка подхватывается за 1–2 секунды |
| П-25 | Пять быстрых нажатий перемотки | Один переход, а не пять |

### 6.4. Документация

Сдаётся вместе с кодом:

- README: установка, настройка, запуск — по шагам, без предположений
- Совместимость кодеков по платформам и что делать, если файл не пошёл
- Описание интерфейса источников с рабочим примером
- Развёртывание: systemd, Docker, обратный прокси с HTTPS, чек-лист перед
  открытием доступа наружу
- Диагностика: пустой каталог, пустая библиотека, не сопоставился фильм,
  не играет на телевизоре, медленная перемотка

## 7. Этапы

| Этап | Содержание | Доля |
|---|---|---|
| 1 | Каркас сервера, конфигурация, хранилище, вход и профили | 10% |

| 3 | Индексация библиотеки: обход, разбор имён, ffprobe, сопоставление | 20% |

## 8. Как проверять исполнителя

Раздел для заказчика. Балансер, каталог, «подключить API» — это не то, на чём
проваливаются. Проваливаются на пунктах ниже.

### 8.1. Вопросы на собеседовании

1. **«Сайт отлично работает на ноутбуке, а на телевизоре при перемотке вечный
   спиннер. Где смотреть?»**
   Ожидаемо: байтовые диапазоны. Сервер не отдаёт `206`/`Content-Range`, и
   телевизор при каждой перемотке качает файл с нуля. Кто говорит про «медленный
   интернет» или «надо HLS» — не понимает, как работает `<video>`.

2. **«Пользователь идёт вправо по ряду постеров и вдруг оказывается в ряду
   ниже. Почему?»**
   Ожидаемо: навигация ищет ближайший элемент, не взвешивая отклонение по
   поперечной оси. Нужен большой штраф за поперечное смещение и приоритет
   пересекающимся по вертикали элементам.

3. **«MKV играет на телевизоре и не играет на iPad. Что делать?»**
   Ожидаемо: Safari не поддерживает MKV. Либо вторая копия в MP4 с H.264/AAC,
   либо транскодирование. Правильный ответ включает `-movflags +faststart` и
   объяснение, почему без него перемотка по сети тормозит.

4. **«Карусель на телевизоре идёт рывками. Первое, что выключаете?»**
   Ожидаемо: `blur`/`backdrop-filter` и крупные тени, анимации не по
   `transform`/`opacity`. Кто начинает с «добавим виртуализацию» — не пробовал.

5. **«Почему нельзя размонтировать карточки, ушедшие за левый край ряда?»**
   Ожидаемо: сломается навигация назад — движку нужен существующий элемент,
   чтобы найти путь.

6. **«Как поведёт себя приложение, если внешний каталог ответил 500?»**
   Ожидаемо: ряд пропускается, остальное работает. Кто отвечает «покажем экран
   ошибки» — не думал о зрителе.

7. **«Куда сохранять позицию просмотра, если телевизор выключают кнопкой на
   пульте?»**
   Ожидаемо: периодическое сохранение плюс `pagehide`. `beforeunload` на
   телевизорах срабатывает не всегда.

### 8.2. Тестовое задание

Небольшое, проверяет ровно рискованные места. Два-четыре часа работы.

**Задание.** Страница с горизонтальным рядом из 50 карточек-заглушек и
видеоплеером под ним, отдающая локальный файл.

Требуется:
1. Навигация крестовиной по ряду и переход к плееру вниз.
2. Отдача файла с поддержкой байтовых диапазонов, включая суффиксные и `416`.
3. Ленивая загрузка изображений.
4. Сборка под Chromium 61.

**На что смотреть в результате:**

| Признак | Оценка |
|---|---|
| `curl -H 'Range: bytes=-50'` работает | Понимает спецификацию, а не копировал сниппет |
| `416` с `Content-Range: bytes */размер` | Читал спецификацию |
| Обработаны и `key`, и `keyCode` | Работал с телевизорами |
| Отклонение по поперечной оси взвешено | Думал, а не брал ближайший элемент |
| Прерванный поток закрывает файл | Понимает потоки |
| `target` в сборке указан явно | Понимает, зачем |
| Обошёлся без тяжёлых библиотек | Думает о телевизоре |

Красные флаги: подключены Next.js и UI-кит ради одной страницы; диапазоны
считаются вручную без проверки границ; `scrollIntoView({behavior:'smooth'})`
как единственный способ прокрутки (не работает на webOS); фокус через
`element.focus()` без своего слоя навигации.

### 8.3. Оценка сроков

Ориентир для одного опытного исполнителя на полной занятости — 5–7 недель.
Оценка меньше трёх недель означает, что человек не увидел объём: разбор имён
файлов и навигация пультом съедают времени больше, чем весь каталог.
